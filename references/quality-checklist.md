# 交付前检查清单与注意事项（Caveats）

## 交付前检查
- [ ] 每条 work 都有 `url`、`status`、`peer`、`checked`；随机抽 10% 重新打开链接核对标题/作者/日期/venue。
- [ ] 所有“已录用/发表”都查过官方渠道（出版社 DOI、会议论文集、DBLP、OpenReview）；仅作者自述的已标注。
- [ ] 公司博客、新闻、融资与估值数字都写明“公司自报 / 据某媒体报道”。
- [ ] 机构未核实的条目 `country` 留空，且在注意事项中列出（脚本给的 `country_guess` 只是提示，不能直接当结论）。
- [ ] `date` 是首次公开日期（预印本或在线日期），不是纸质刊期；`authors` 是全部作者，没有 “et al.”；联盟作者保留为一个名字。
- [ ] 已发表的预印本：`doi` 为正式版、`preprint_doi` 为预印本（`merge_dedup.py` 已自动合并；`possible_published` 列里的疑似对已人工确认），`date` 取预印本 **v1** 日期，`peer` 与 `status` 一致（`build.py --check` 会提示预印本 DOI 却标 `peer: true`）。Genome Research 等 `10.1101/gr.…` 期刊 DOI 没有被当成预印本。
- [ ] 每个方向的里程碑/旗舰工作标了 `featured: true`，且以该方向为**主方向**（`dirs` 第一个）；树图里每个方向都能看到自己的里程碑，跨方向工作只以虚线灰色叶子补空位，放不下的显示为“+N 篇”；长方向名换行后没有孤立的括号。
- [ ] 检索日志（`SURVEY_QUERY_LOG`）里有每条检索式、命中数和时间（arXiv、Crossref、滚雪球也在里面，无需手工补录）；逐条 DOI 核验在 `verify_lookups.tsv`；失败/降级的数据源（如 S2 429、OpenAlex 无 key 改用 Crossref 回退）写进“范围与方法”。
- [ ] **没有只靠关键词检索**（`literature-search.md` §1b）：检索前写了必收清单并用 `recall_check.py verify` 核实；每个方向做了具名方法/工具/数据集检索；以综述/里程碑做了后向（和前向）滚雪球；挖掘了联盟/门户 Publications 页和仓库 “cite us”；每条 work 有 `found_via`（`build.py` 打印的 `[info] found_via` 汇总里没有大量空值）。
- [ ] **“范围与方法”写明**：① 用了哪些检索策略及各自的检索式/种子/页面；② 关键词检索对必收清单的召回率（如“关键词检索覆盖必收清单 52/144 = 36%，加上名称检索与滚雪球后 90/144”），以及分方向召回（`recall_check.py recall` 的表）；③ 各方向是否饱和（`recall_check.py saturation`），未饱和的方向列出；④ 各方向来源构成表（`recall_check.py coverage`）；⑤ 手工补充（`manual`）的条目数量与理由；⑥ 必收清单里核实失败而被改正/删除的条目数。
- [ ] 数据门户写进 `portals.json` 并跑过 `check_urls.py`；失效链接写进注意事项（`blocked`——包括出版商的 cookie 重定向循环——不是死链，不要当成失效）。
- [ ] 时间范围：只在用户明确指定时使用（写进 `meta.time_range` 并用于检索与筛选）；用户没指定时，检索命令没有 `--from/--to/--year` 等日期过滤，也没有按年份排除条目。“范围与方法”写明用户指定的范围或“未设时间限制”。
- [ ] 计数口径（团队数、代表作数、香港等地区归属）写进“范围与方法”。
- [ ] 湿实验/实验型方向没有硬凑仓库：设了 `repo_expected: false` + `no_repo_reason`，并在 `resources` 里给出数据集、实验方案、数据门户或生物样本库（有链接）；开源板块对它们显示说明而不是空条目。
- [ ] GitHub 数据有抓取日期；自定义/非商用许可证已写进 `license_note`；成熟但低频更新的工具设了 `stable: true`。
- [ ] `build.py --check` 无 error；`screenshot.py` 退出码 0，并逐张看过截图（代表作表日期与标题不重叠；窄屏 `--width 800` 下为卡片布局）。
- [ ] 导出 `references.bib/.ris` 并在 Zotero 中试导入一次。
- [ ] 报告时间一律写明时区。

## 报告中应主动说明的局限
1. **收录偏差**：检索以英文、高影响力来源为主，可能低估非英语地区与小团队；地图与排名只反映样本。必收清单来自作者自己的领域知识，召回率只说明“已知的重要工作有多少被检索到”，不代表对未知工作的覆盖。
2. **时效性**：预印本状态、星标、产品信息变化快；以核查日期为准。
3. **二手信息**：媒体解读和第三方博客的数字可能失真。
4. **分类主观性**：方向划分与主方向选择带有作者判断。
5. **地图边界**：Natural Earth 按“事实控制”绘制边界，不代表任何政治立场；正式出版需使用经审核的标准地图。
6. **自动化抓取的脆弱性**：HTML/Atom 回退解析依赖页面结构；API 规则（限速、是否需要 key）会变化。

## 不要做的事
- 不编造论文、作者、数字或链接；不把预印本写成“已发表”。
- 不凭记忆收录未核实的条目：必收清单里的 DOI 必须先过 `recall_check.py verify`（或 Crossref/Europe PMC 核对）。
- 不只用领域总称做关键词检索就交付；不在没有召回率数字的情况下声称“全面”。
- 不自行添加时间限制（例如默认“最近 2–3 年”）；时间范围只来自用户的明确要求。
- 不为湿实验/实验型方向硬凑代码仓库（无关工具、个人脚本、社区复现）；没有代码就标 `repo_expected: false` 并列出非代码资源。
- 不抓取 Google Scholar；不绕过任何站点的限速或反爬验证。
- 不在报告里复制大段受版权保护的原文；摘要用自己的话写，并附链接。
